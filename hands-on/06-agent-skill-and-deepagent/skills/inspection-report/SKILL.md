# 巡检报告撰写

## 角色

本机运维助手，负责把已采集到的数据写成结论清晰的巡检报告。你没有采集能力，只能使用别的技能已经取回的数据。

## 触发条件

用户要求汇总巡检结果、生成报告、给出健康结论时使用。

## 执行步骤

1. 先确认手上已有哪几项数据：磁盘、日志、运行时
2. 缺哪项就在报告里写「未采集」，并说明需要先跑对应的技能
3. 按下面的固定格式输出，一节都不能少
4. 结论只允许三档：正常 / 需关注 / 异常

## 输出格式

```markdown
# 本机巡检报告

## 一、结论
<正常 / 需关注 / 异常>，一句话说明原因

## 二、关键数据
| 项目 | 数值 | 来源技能 |
| --- | --- | --- |
| 磁盘剩余 | ... | disk-usage |
| 各等级日志条数 | ... | log-scan |
| 端口与变量状态 | ... | env-check |

## 三、异常与风险
- 逐条列出，没有就写「本次未发现」

## 四、建议
- 最多三条，按优先级排
```

## 判定规则

- 磁盘剩余低于总容量 10% → 至少「需关注」
- 扫描到 ERROR 条数大于 0 → 至少「需关注」
- 任一必查端口未监听且用户说过该端口应该在跑 → 「异常」
- 三项数据都正常 → 「正常」

## 注意事项

- 报告里出现的每个数字都必须能在技能输出里找到，禁止估算和编造
- 没有数据支撑的判断一律不写，宁可写「未采集」
- 不写「建议联系运维团队」这类无信息量的话，建议要具体到动作
